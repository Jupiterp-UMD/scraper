# Jupiterp database schema

Every table, matview and view in the `public` schema: what it holds, what
writes it, what reads it, and what is easy to get wrong about it.

`README.md` in this directory covers how migrations are applied. This file
covers what they produced.

Row counts are a snapshot taken **2026-08-21** against the rehearsal clone
`dyoqrtratubmehumbbhx`, not production. Catalog, instructor and grade counts
track production closely because they come from the same scrapes; the review
and moderation counts are test data and mean nothing.

## How to read the "read by" column

Nothing outside this repo talks to Postgres. The site and the npm package
reach the database only through the Go API, so a table's real consumer list is
the API endpoint that surfaces it. Where a row says a table is read by the
site, it means the site reads an endpoint that reads that table.

Two roles matter. `anon` is what PostgREST uses for unauthenticated reads and
is the blast radius of a bad grant; `service_role` is what the API's write
client and the scraper use, and it bypasses RLS. The **Public** column below
records whether `anon` can select the object at all.

## Instructor identity

The largest source of complexity in the schema, and the reason most of the
migrations exist. A professor is named three different ways by three different
sources — Testudo, the registrar's grade files, PlanetTerp — and the whole
point of this group is to make those one record.

### `instructors` — 15,152 rows

The canonical professor record. `id bigint` is the identity everything else
joins on; `slug` is the public URL and the original primary key.

Carries four groups of columns: identity (`name`, `slug`, and `name_norm`,
generated by `normalize_name(name)` and indexed for trigram search),
PlanetTerp provenance (`pt_slug`, `pt_average_rating`, `pt_review_count`,
`pt_snapshot_at`), computed ratings (`jupiterp_rating`,
`jupiterp_review_count`, `combined_rating`, `average_rating`), and activity
(`first_seen_term`, `last_seen_term`, `is_active`).

> `is_active` is the **definition** of "currently teaching" since 0035 —
> `active_instructors` selects on it and `/v1/instructors?activeOnly=true`
> filters on it. Its only writer is `set_active_instructors()`. Do not set it
> by hand.

> `average_rating` is a legacy alias of `combined_rating` kept so v0 clients
> keep working. Write `combined_rating`; `refresh_instructor_ratings()` keeps
> the two in step.

| | |
| :-- | :-- |
| Written by | `link_instructor()`, `set_active_instructors()`, `refresh_instructor_ratings()`, `merge_instructors()`, `resolve_instructor_match()`, `snapshot_planetterp.py` |
| Read by | `/instructors`, `/instructors/active`, professor pages, the sitemap, the admin triage screen |
| Public | yes (RLS on, with a `PUBLIC` read policy) |
| Never | truncated — guarded by `NEVER_TRUNCATE` in `scraper/db.py` |

### `instructor_aliases` — 15,424 rows

Every observed spelling → exactly one instructor. `alias_norm` is the primary
key, so a spelling cannot mean two people. `source` records where it was seen
(`testudo`, `planetterp`, `registrar`, `manual`) and `confidence < 1.0` means
the link was inferred rather than seen.

This is what makes `Aaron Kyei-Asare` and `Aaron Kyei-asare` the same person
without anything ever comparing name strings at query time.

> **Append-only.** Deleting a row does not just lose an alias — it orphans
> every grade row matched through it, and the resolver then re-queues that
> name for a human who has no way to know it was already decided.

| | |
| :-- | :-- |
| Written by | `link_instructor()`, `resolve_instructor_match()`, `merge_instructors()`, `override_instructor_match()` |
| Read by | `resolve_instructor()`, `refresh_section_instructor_slugs()` |
| Public | no |

### `instructor_match_queue` — 1,270 rows (254 open)

Names the resolver refused to guess at. `observed` plus a generated
`observed_norm`, the `source`, a `context` jsonb of `{course_code, term,
sec_code}`, and `candidates bigint[]` — ids that nearly matched, so triage is
a choice rather than a search. Resolution stamps `resolved_to`, `resolved_at`
and `resolved_by`.

A partial unique index on `(observed_norm, source) where resolved_at is null`
keeps a name that appears in 400 sections from queuing 400 identical
decisions.

> `candidates` is a bare `bigint[]` with **no foreign key**, so an id can
> outlive the instructor it named. `instructor_match_queue_detail` drops dead
> ids rather than showing blank rows; `merge_instructors()` rewrites them to
> the survivor.

| | |
| :-- | :-- |
| Written by | `link_instructor()` (enqueue), `resolve_instructor_match()`, `override_instructor_match()` |
| Read by | `/v1/admin/instructors/queue`, `scraper/ci.py` (open-count ceiling) |
| Public | no |

### `section_instructors` — 8,586 rows

`(course_code, sec_code, instructor_id)`, the id-keyed companion to
`sections.instructors[]`. Answers "which instructors are teaching right now"
without a name match.

Since 0035 it no longer backs `active_instructors`. It remains the
foreign-key record tying sections to instructor ids, the source of the
per-candidate "sections now" count in triage, and CI's cross-check against
`is_active`.

| | |
| :-- | :-- |
| Written by | `swap_section_instructors()` only |
| Read by | `instructor_match_queue_detail`, `scraper/ci.py` |
| Public | no |

### `section_instructors_staging` — 0 rows between scrapes

`UNLOGGED` scratch copy of the above. The scraper uploads a run's links here in
chunks (PostgREST rejects very large bodies), then `swap_section_instructors()`
replaces the live table from it in one transaction and truncates this one.

The staging table exists so the swap is atomic: `active_instructors` used to
go briefly empty mid-scrape, and a single cache miss inside that window pinned
an empty professor list for up to a day.

| | |
| :-- | :-- |
| Written by | `scraper/instructor_registry.py:_rebuild_section_instructors` |
| Read by | `swap_section_instructors()` and nothing else |
| Public | no |

## Grades

### `grades` — 203,579 rows

Section-level grade distributions, sixteen years of them. Keyed
`(term, course_code, sec_code)` with a count column per letter grade, plus
`w`, `other`, `total`, a generated `graded` and `gpa`.

Three columns describe the instructor: `instructor` and `instructor_name` are
the registrar's raw strings, `instructor_source` records how the name was
obtained, and `instructor_id` is the resolved link. `instructor_id` is
nullable and its FK is `ON DELETE SET NULL`.

| Public | yes |

### `grade_ingests` — 31 rows

## Reviews and moderation

Counts here are clone test data. This group is the only part of the schema
that stores anything a user typed, and the only part with meaningful RLS.

### `reviews` — 16 rows (clone)

Student reviews. Content (`rating`, `title`, `body`, `expected_grade`,
`course_code`, `term`), lifecycle (`status`, `submitted_at`, `verified_at`,
`moderated_at`, `moderator`, `reject_reason`, `edited_at`), triage bookkeeping
(`triage_attempts`, `next_triage_at`), and hashed identity (`email_hash`,
`email_domain`, `edit_key_hash`, `submit_ip_hash`, `user_agent_hash`).

> `anon` cannot read this table at all. Public review content is served only
> through the `public_reviews` view, which exposes approved rows and does not
> make the identity columns selectable.

> The FK to `instructors` is `ON DELETE CASCADE`. Deleting an instructor row
> destroys their reviews — which is why `merge_instructors()` reassigns
> reviews before it deletes anything.

## Operational

### `schema_migrations` — 36 rows

The migration ledger: `version`, `filename`, `checksum`, `applied_at`. Written
by `migrate.sh` inside the same transaction as the migration it records, which
is what makes "applied" and "actually ran" the same statement. The checksum is
what refuses a migration edited after it ran.

### `user_data` — 0 rows

Two columns (`id`, `created_at`), no rows, and **no reader or writer anywhere
in this repo**. Predates the migrations and was never captured in
`baseline/`. Treat it as vestigial; confirm before assuming otherwise.

## Things that bite

**Seven tables must never be truncated**, and `scraper/db.py` raises rather
than letting the nightly snapshot path touch them: `instructors`,
`instructor_aliases`, `instructor_match_queue`, `section_instructors`,
`grades`, `grade_ingests`, `reviews`. The guard exists because the
`instructors` branch of that function was *removed* rather than never having
existed, and copying the line above it is the obvious way to add a new table
to the scrape.

**Three foreign keys into `instructors` are `ON DELETE CASCADE`** —
`instructor_aliases`, `reviews`, `section_instructors` — and
`instructor_match_queue.resolved_to` is `NO ACTION`. So deleting an instructor
row destroys reviews and aliases, nulls grade attribution, and then fails
anyway if that record ever answered a queue entry. Use `merge_instructors()`,
which reassigns everything first.

**The matviews are the quietest failure in the schema.** Nothing errors when
they go stale; the site just serves last term's numbers.

**Two sets of "who is active" still exist.** `instructors.is_active` is the
definition; `section_instructors` is the FK record. They are written by two
RPCs that `reconcile_instructors()` calls in sequence — each atomic, the pair
not — so `ci.py:_check_active_flag_matches_section_links` compares them after
every run.
